# Changelog

**Language:** [English](./CHANGELOG.md) · [Français](./CHANGELOG.fr.md)

All notable changes to this project are recorded in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/).

This repository is a **content catalog**, not a library: it publishes no PyPI
package and no wheel. A `vX.Y.Z` tag does publish a GitHub release, though — an
archive of the catalog, its SHA-256 digest, SLSA level 3 provenance and a
cosign signature (see `RELEASING.md`). The unit that matters is still the lab.

## [0.2.0] - 2026-10-17

### Changed

- **The validator reads the contract, not the terminal panel.**
  `scripts/valider-labs.py` parsed the score out of what `dsoxlab check`
  *displays*. That panel is interface: it changed in dsoxlab 0.4.0 and the
  regex stopped finding anything. It now reads `check --json`, which carries a
  `schema`, and the reading lives in `scripts/verdict_check.py`, **identical in
  all twelve catalogs**.

- **Three verdicts, not two.** A run where every collected test skipped
  measured nothing: it is **SKIP**, neither green nor red, and it stays to be
  measured. Painting it red would accuse the lab of what is missing from the
  machine. `--check` therefore exits `10` in that case, against `1` for a RED,
  mirroring `dsoxlab doctor --strict` where 9 is repaired and 10 is remeasured.

- **The README takes the reference structure** shared by the twelve catalogs:
  fourteen sections, in both languages. Seven of them describe dsoxlab rather
  than the subject, and are therefore identical everywhere.

### Requires

- **dsoxlab 0.4.1 or later**, which introduced the `status` field of
  `check --json`. Without it the validator refuses to conclude rather than
  guessing.

### Also

- les dix `doc_url` pointent vers le site public et non la préproduction.

## [0.1.0] - 2026-10-14

First version of the catalog: ten labs, all `runtime: shell`, proven in both
directions.

### Added

- **The common thread, six labs building a single tool, `certcheck`**
  (the "Developing for Ops" course). Each lab starts from the previous one's
  reference solution, which is shipped in clear for that reason:
  - `lire-du-code` — read and modify a small Python script: the inherited
    `certcheck`;
  - `script-en-outil` — understand a Python tool, then modify it: `certcheck`
    and its contract;
  - `dependances-reproductibles` — dependencies: `certcheck` installs
    elsewhere too;
  - `tester-une-automatisation` — use the tests: a red test, read, fixed, and
    one more test;
  - `deboguer` — debug step by step: the certificate `certcheck` cannot read;
  - `relire-une-automatisation` — review a pull request: four defects in
    `certcheck` #42.
- **The optional `approfondir` section**, three standalone labs played after
  the common thread:
  - `appeler-une-api` — call an API with `requests`: `certcheck` opens its
    ticket;
  - `livrer-un-outil` — ship a tool: `certcheck` 1.0.0, versioned and
    installable;
  - `level-exams-outil` — challenge: take over an operations tool.
- **The `level-exams-intervenir` level exam**: a repository of five commits,
  one of them faulty, a red CI log, a bounded fix, with tests, quality checks
  and CI steps replayed. Generated by `scripts/generer_depot_intervenir.py`
  from `donnees/intervenir/`.
- The English README table flags the guides that only exist in French.
- **All ten labs proven in both directions** by `scripts/valider-labs.py`: 0
  before the work, the full score after the solution, 0 again after `clean`
  and `run`, and the machine left as it was found. Verdicts in
  `validation-labs.json`.

### Fixed

- `scripts/valider-labs.py` was not photographing the lab but **the whole
  machine**: its unfiltered `docker ps -a` saw containers from every project on
  the host, and two labs turned red over containers they had never touched.
  The photograph is now limited to what dsoxlab can create — the `dsoxlab-`
  prefix and the `spawns` declared by the labs, read from the catalog so that a
  future service is watched without anyone having to remember.
- The `doc_url` fields and guide links point at `dev.stephane-robert.info`,
  where this course's guides are published. Links to pages already live on
  `blog.stephane-robert.info` are unchanged.
- Documentation drift inherited from `github-actions-training`, which this
  repository is derived from: an `automatisation-dans-la-ci` lab that does not
  exist, a `security_check.py` tool that is not the one the common thread
  builds, an `automatisation` section missing from `meta.yml`, an `.actrc` and
  a Docker requirement that exist nowhere here, and a `--lab` example naming an
  unknown lab.
